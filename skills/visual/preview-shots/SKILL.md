# 预览截图

把值得评审的图像放进用户面前的一个可翻页的 Preview 窗口。

## 工作流

1. **精选集合** —— 能回答"这是对的吗？"的图像：刚变更或刚被认可的基线、整合后的结果，以及有东西可比时的参考图。不要把文件夹里每张 PNG 都倒出来；挑出让用户能判断变更的最小集合。用户点名了具体截图时，就精确打开那些。
2. **一个窗口** —— 用一次 `open -a Preview <path> <path> ...` 调用打开它们。一次 `open` 调用会把所有文件放进一个带缩略图侧栏的窗口；分开调用会开出分开的窗口。
3. **给它们写说明** —— 每张截图一行（它是什么），让用户知道自己在翻什么。

## 规则

- 仅限 macOS（`open`）；传入绝对路径或仓库根相对路径。
- 文件按最重要在前排序；Preview 打开时显示第一个。
- 评审已保存的 PNG/GIF 产物，不是实况 Chrome。精确的回归截图默认应以无头方式运行；只有用户明确要求实况浏览器，或在复现仅 headful 才有的 bug 时才打开 Chrome。
- **一次一组——绝不堆积窗口。** 打开新一组之前，关闭已打开的组：`osascript -e 'tell application "Preview" to close every window'`。
- **无人值守推进时关闭。** 当你为一次非阻塞评审打开了截图、随后在没有用户回应的情况下继续前进时，之后关闭 Preview：`osascript -e 'quit app "Preview"'`。通宵自主运行绝不该让用户醒来面对一墙的 Preview 窗口——至多一组打开，且越过检查点之后一组都不留。
