# 发布视频

标准是一部 **showreel**：动态设计师放在简历里证明自己多出色的那种作品——有动感、有野心、配乐到位、真正的专业制作，绝不是 demo 或原型。全力以赴。仓库提供故事；手艺是你的。这里没有任何东西是模板：如果这部片子换层皮就能用于任何其他项目，那它就失败了。

## 工作流

1. **找到故事。** 阅读 README、文档、基准测试和品牌美术素材。当你能各自带出处在内地说清以下三点时完成：它是什么（一句话）、它在底层如何运作（观众是技术人员）、以及值得落地的证据。仓库无法支撑的说法要标出来，而不是替它编造含义。
2. **先做导演，再动手建。** 选择一个从项目*本身*生长出来的视觉概念（它的隐喻、它的品牌美术、它的机制）：一个有自己的外观、镜头和标志性动作的世界，而不是一串面板。然后为机制选定一个人人熟悉的现实类比（建一座城市、经营一个厨房、一场劫案），把每一步映射上去：用类比的词汇为每一步命名，并给每一步配上扫一眼就能看懂的日常道具（测量仪的三脚架、木桩、起重机、验收章）。易懂胜过炫技：观众应该从他们已知的参照物读懂每一步，一个字都不用读。把它写成音乐时间轴上的分镜清单。当每个分镜都写明它的镜头运动和动态设计师会为之自豪的那一刻时完成。描述是"一张卡片/面板/列表出现"的分镜要重新设计。
3. **让画面和配乐来自同一个计时源。** 每个事件时间都住在一个地方，场景和音轨都读它，这样节拍才能落在节拍上。在代码里合成音乐能把这把锁锁得最准。
4. **以导演身份评审。** 渲染一版草稿，把每个分镜平铺成 contact sheet，让一个没见过你的方案的子智能体做一次初见式点评。然后对每个分镜问那个 showreel 问题。修复并重渲染，直到每个分镜都通过，而不是抽样。
5. **交付。** 制作缩略图（规则见下），渲染母版（1080p60、高质量 H.264、320k AAC），在 Finder 中显示，并把项目作为独立包提交进仓库：渲染产物和生成的音频设为忽略，附一份简短 README，涵盖命令、计时原理，以及保存在影片之外的论断来源和方法。

## 是营销，不是白皮书

以产品和几条令人记得住的好处开场。方法论、样本量、缺失数据的处理、基准测试的注意事项和来源引用放进包的 README 或链接的报告，不要放进视频或主视觉。不要加小字、星号脚注、免责声明块或防御性旁白。如果一个说法需要收窄才能保持为真，就收窄标题本身；绝不用小字去挽救一个误导性的标题。逐帧检查阅读负担，也检查视觉质量。

## 展示，不要讲述

文字是最后手段。任何字上屏之前，先找到让它变得不必要的画面：一个变形的物体、一个变化的世界、一个把想法演出来的动作。只在视觉无法承载时保留文字：产品的真实命令、它的名字，和必须精确的论断。唯一的例外是定向：给每个分镜一个说明正在发生什么的标题（它可以有动感，比如一个随动作跳动的实时计数），否则再好的动画看起来也像乱动。当草稿依赖标签、字幕或副标题来解释正在发生的事时，重新设计分镜，而不是改措辞。

## showreel 问题

动态设计师会把这一镜放进自己的 reel 吗？表明它滑向解说片或 demo 的征兆：

- **动画幻灯片。** 静态布局，元素滑入然后停住。reel 的镜头永远在去向某处，构图持续变化。
- **在阅读，不在观看。** 大段文字、UI 卡片、正文文案，或标题下的副标题（需要副标题的标题就是两个想法）。reel 用戏剧尺度上的短语爆发说话，机制由画面承载。
- **破碎的隐喻。** 一个动作没有做到它所描绘的事：一次剪切无视它声称分开的部分，一个贴在任何底色上都读不清的标签。让运动对屏上的物体诚实。
- **只有一个把戏。** 每个元素都以同一种方式弹出。reel 展示广度：纵深与视差、尺度对比、把元素带入下一镜的匹配剪切与转场、变速、光与色的变化、粒子与物理、作为设计而运动的文字排版。
- **平。** 一切都坐在同一平面同一尺度上，没有前景、背景或光。
- **聋。** 运动无视音乐，或音乐只是垫在画面下面而不是驱动画面。
- **原型级 3D。** 平光下无贴图的几何体，没有镜头：它读起来像技术 demo。如果片子走 3D，就按游戏过场动画的标准做完：带表面细节和受光倒角的基于物理的材质、反射与软阴影、会泛光的发光体，以及一个镜头（环境光遮蔽、景深、噪点、撞击时的色差）。

## 规则

- **重建，绝不截图。** 把任何 UI 拆解成可以运动的部件。
- **在渲染出的帧里评判效果，绝不在实时预览里。** 逐帧渲染器（比如 Remotion 的手动步进）可能悄悄丢掉一个后处理栈或一层画布，而实时看起来没问题。
- **论断保持精确。** 对照来源核实标题里的论断，并在标题里保持其范围清晰。把支撑证据保存在文档里；哪些该上屏遵循上面的营销规则。
- **你听不见。** 用测量验证混音（整体响度约 −11 到 −14 LUFS，以及一张显示 riser 和撞击落在各自提示点上的频谱图），并在交接中说明音频是靠测量检查的，不是靠耳朵。
- **缩略图。** 信息流（X）会取较早的一帧，并跳过单帧海报，所以让预览帧保持约 0.3 秒的预卷，再把它移进开场（音乐同步移相同的量）。让预卷背景与开场匹配，以免播放时闪一下。最好的预览是产品在做它的工作（名字、标语、一条已完成的命令和它的输出）；标题数字要有它的兑现镜头，另出一张单独的主视觉静帧。
