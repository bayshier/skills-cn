# GPU 渲染器

技术栈是 **WebGPU 上的 TypeGPU**：带类型的 schema、bind group layout 和管线，在更清晰的地方用 WGSL。不要引入第二个渲染库。

3D 模型和纹理用 Blender（如果可用）。已安装 Blender MCP server 时优先用它；否则无头运行（`blender -b --python script.py`）。脚本保留在仓库里，让每个资产都能从代码复现，而不是手工编辑。

## 架构

- **渲染器只画交给它的东西。** 应用从自己的状态（游戏观测、查询结果、文档）构建普通的帧输入，渲染器通过一个接口消费它们。它绝不伸进应用或领域状态。
- **一个帧函数负责编排。** 单个函数按顺序编码每个 pass。添加任何东西之前先读它，把你的 pass 加在那里，而不是旁边。
- **按语义选择阶段：**
  - compute 用于准备（剔除、布局、实例构建）；
  - 不透明几何体先做深度 prepass，然后是受光的颜色 pass；
  - 半透明内容排在 opaque 之后；
  - 屏幕空间 pass 画在 resolved 目标上；
  - overlay 和 UI 最后。
- **每个概念一个属主：** device 与能力、相机与投影、深度约定、帧目标、资源注册表、时间源。第二份拷贝（一个私有投影，或一个在 WGSL 里手工镜像的 struct）是等着发生的 bug。重构到共享属主。
- **可调数值放在数据里**（config 或 fixtures），在加载处校验。不要在 pass 里散落常量。
- **按各自的频率更新每种资源：** 每帧、视图变化时、数据变化时（只上传增量），或一次。热路径上每帧不分配任何东西。
- **CPU 侧数学使用 pmndrs 的 [`math`](https://github.com/pmndrs/math) 包**（npm 包名 `math`，其 `API.md` 列出全部导出）：向量、矩阵、四元数、视锥与形状剔除、噪声、带种子的随机数。
  - 它的函数把输出作为第一个参数并返回它，所以预分配的 scratch 让热路径零分配。
  - 把它的结果装进预分配的 `Float32Array` 供上传。
  - 不要手写第二个向量或矩阵库。
- **拾取与命中测试使用应用自己的形状**，以及 GPU 打包所用的同一相机函数，绝不回读已画好的像素。

## 资源

- **每个 buffer 和纹理都经过一个注册表，** 内含按大小区分目标的 scope 和可替换资源的槽位。任何东西都不在它之外分配：TypeGPU 里 `root.destroy()` 不会释放 root 创建的东西。
- **处理异步重建**（resize、管线切换）。构建到新的 scope 再整体换入。释放被超越或在 dispose 之后才完成的构建。让每个公开调用在 `dispose` 之后仍然安全。
- **当上传与派生资源烘焙共享可变 GPU buffer 时，序列化整个替换事务。** 只串行化上传仍会让一次更旧的回读装入过时结果；要保留调用方的错误，又不毒化后续请求。
- **添加一个测试：resize、重建和反复重置之后，计数与字节数回到基线。**

## 深度、混合与目标

- **深度是一份访问契约**（`read`、`read-write`、`prepassed`），约定是引擎级的。在 `depth32float` 上优先 reverse-Z（clear 0，比较 `greater`）。比较方向、clear 值与格式要么一起变，要么都不变。
- **不透明几何体从不 alpha 混合。** 半透明 pass 读深度且从不写深度。
- **分段绘制的线条按构造接合。** 加法叠加的段落互相重叠并在重叠处淡出，接缝相加为一；混合的段落切成方角，因为两次过度合成的淡出永远不会加回一。同一物体的多个混合层按层序绘制，而不是按其段落的生成顺序。
- **动态光是每种材质经由同一个着色函数读取的数据。** 特效提供一份每帧有上限的短命点光列表；共享的着色调用为每个受光层求和它们。光晕精灵提亮的是空气，绝不是它周围的表面；每层私设的打光偏方会与其他层漂移。
- **overlay 与 UI 在后处理之后合成，** 不受光、不调色。属于世界的东西画在世界里。
- **深度 prepass 与颜色 pass 共享同一个顶点阶段，** 位置带 `@invariant`，两者的深度逐位一致。
- **使用 4× MSAA**（WebGPU 保证的倍数）。后续屏幕空间测试依赖的 varying 一律在质心处插值。

- **每个标注作为一个组整体合成。** 它的衬底画在前景笔画之下；选中优先级移动整个组。通过绘制顺序解决遮挡，不要擦除本应有的衬底覆盖。特效尾迹的边界与堆叠分开约束。

- **约束最终渲染出的几何体，包括每个独立的倍增器和画出的 LOD。** 给 shader 变化的界限、CPU 校验和剔除指定一个属主。依赖视角的宽度扩展不得悄悄扩大高度；仅凭源尺寸证明不了最终尺寸有上限。

## TypeGPU 与 WebGPU 的坑

- **GPU 探测中使用同一个 TypeGPU 模块实例。** 把 bundler 优化过的导入与直接的包 URL（或不同的缓存查询）混用会复制内部符号：导入的 shader 函数可能从解析中悄悄消失，WGSL 报一个未解析的调用。改 shader 代码之前，先核对 pass 实际使用的模块 URL。
- **只固定共享相机的 bind group**（`$idx(0)`）。其余由 TypeGPU 编号。
- **没有 fragment 阶段的管线是合法的。** 深度专用的 pass 用它，而不是写 `frag_depth`——后者会禁用 early-Z。
- **WGSL 的 `let` 不可变。** 重新赋值会让管线失效，而应用看起来一切正常。
- **WGSL 预留了它还没用的词**（`cast`、`meta`……）；以它们命名的标识符在解析期就让模块失败。
- **uniform 结构体按 16 字节对齐补齐。** 在每个 schema 旁放一个字节大小常量，并针对它测试打包器。
- **默认 bind 限制很小**（每阶段 8 个 storage buffer）。加一个之前先数一数。
- **Apple GPU：**
  - 一个 pass 什么都没画的 tile 会跳过 resolve，所以一张被加载的目标可能在那个 tile 显示旧帧。让背景 pass 也 resolve。
  - 时间戳查询只有作为整帧总量才有意义。
- **CPU 侧矩阵也保持 float32，** 这样 CPU 拾取与 GPU 绘制完全一致。
- **把任何验证警告或控制台错误当作渲染失败。**

## 验证

- **动画使用一个可注入的时钟。** 绝不在 pass 内使用 `performance.now()`、`Date` 或无种子随机数。被按住的时钟给出确定性的截取。
- **在单元测试中测试打包与 shader 数学的 CPU 镜像。** 然后在跑在真实 GPU 上的浏览器里（不是软件回退）渲染最窄的真实场景，并看这张图。
- **统计不是像素。** 把计数与一个像素或裁剪检查配对，证明主体被画出且取景正确。当类别共享样式时，把条纹与其公布的端点匹配，而不是只看颜色。对连续帧裁剪要跟随快速运动，免得移出静止裁剪框被误读为淡出。
- **从契约推导检查，** 不要照抄常量。只有写下理由才能改像素阈值。
- **在同一台机器上交错测量功能开与关的 GPU 成本，** 而不是两次独立运行。机器上的其他负载会淹没微小差异。

## 战术缩放下的宽度变化

当一次世界空间宽度变化几乎不移动截图时，在再次调参之前，先沿屏幕空间最小值、核心/光晕层和后处理追完整条宽度路径。用相同的相机和事件比较原生的战术视图与近景视图。对移动中的亚像素特征，除了孤立裁剪外，还要在拥挤的实际游戏画面里检查连续帧；一条细静帧可能藏住闪烁，或在地形背景前完全消失。

## 重复运动需要一个完整周期

对节奏或同步类论断，截取启动和多个完整的工作/休息循环，包括其中最长的停顿。为每个 actor 把原生运动帧与源事件时间戳配对；重叠的可见拖尾不能证明同时启动，短暂错开的出场也不能证明持续的相互独立。跨多个种子测试随机时序，报告实测的间隔，而不是承诺不间断的活动。

## 原生生成的身份拥有重叠的景物

空间归属无法辨认一根树干出自哪一片被手工创作的森林。
重叠的形状可能复制树木，或把树冠记到另一个来源头上。从原生生成中导出
不可变的原始来源关联，在消费端保留无损的 prop ID，并让每个来源的树干只放置一次。
当其他形状交错其间时，精确矩形导出序号还需要一份显式的创作 ID 映射。
通过公开导出与生产放置来证明这一点，包括空来源
和生成范围之外的普通道具。

成员归属、数值采样与渲染验收是三个互不相同的论断。保住第一次失败的生产回读及其编译源；一个匹配的成员标记解决不了一次失败的距离预言机。到达停顿点时，保住一个未激活的候选并恢复运行时基线，而不是放宽它的门槛。

## 资源检查需要一致的视图历史

一次被暂停的快进可能在 UI 画出那次发布之前就送完了数据。移动相机之前，先等它的绘制 tick 与呈现时钟。否则一块被保留的 buffer 可能在某次重置时看到一个额外的细节层级，看起来就像泄漏。在改动容量策略或放宽字节断言之前，用实际的分配创建/销毁记录来归因差异。


## 尸体身份不会冻结它的锚点

建筑倒塌后，一个下落中或已静止的尸体的权威来源可能改变它的支撑。为同一尸体身份刷新已发布的位置，而不重启它的死亡动画剪辑、不改变它的朝向、也不让已淡出的尸体重新出现。
静态锚点的变更必须使尸体发布版本失效；只移动缓存对象会让 GPU 实例留在旧高度。敌方锚点来自该阵营最后一次观测到的尸体状态，所以渲染不能从当前物理世界推断一次未被观测到的倒塌。
