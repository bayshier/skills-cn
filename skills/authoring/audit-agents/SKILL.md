# 审计 AGENTS.md

AGENTS.md 会被每一位将来参与这个项目的人阅读。想象未来一百年里的下一千位贡献者：一行字只有在所有文件、工具和依赖都被替换之后仍然为真、且仍然改变他们的做法时，才配留下来。

## 工作流

1. 阅读 AGENTS.md 和根目录 readme。这是文档审计：不运行任何构建，也不运行任何测试。
2. 用下面的测试给每一行一个结论。
   - **保留**：通过所有测试的原则。
   - **改写**：用今天的机制措辞表达的持久教训，或模糊到无法据以行动的内容。
   - **移动**：某人需要的细节。指出它应属的属主：readme、manifest、技能或规格说明。
   - **删除**：重复、历史，或一行什么也改变不了的字。
3. 对照下方的示例检查形态。
4. 汇报发现，影响大的在前。引用每一行的原文，给出结论和替换文本，并归并重复项。引不出原文的发现就不要报。
5. 只有当用户要求重写时才动手编辑。届时从示例开始，写出文件，再以一个没有本次会话历史的新人身份重读一遍。

## 对一行的测试

- **一百年。** 不要命令、标志、路径、文件或函数名、依赖选择、调优值、计划、状态或 bug 故事。保留教训，把机制移交给它的属主。唯一的例外是指向某个属主（readme 或技能）的指针，它存在就是为了让细节住在那里。
- **一千人。** 新人不知道这次会话、这位作者或这个月的工作，也能据以行动。
- **改变他们的做法。** 能干的贡献者本来就会遵守的行，删掉。
- **平实而具体。** 原则不是抽象名词。"看图"有效；"让验证与声明匹配"无效。优先写一句带后果的短句，用产品里的一个例子代替泛泛的名词。
- **迭代速度。** 这是核心原则，必须直白写出：优化到可信反馈为止的时间，运行能回答问题的最窄检查，并在一份规格说明的实现完成时运行全部检查。给每个循环都增加流程的规则、把完整运行放在提交、合并、推送或完成功能之前的规则，以及为此沿途设置检查点的规则，都要标记出来。只有当下一步工作没有完整运行就不可信时，完整运行才提前。绝不用真正的验收要求换取速度。

## 形态

[`assets/example-agents.md`](assets/example-agents.md) 是任何项目都能采用的 AGENTS.md，章节顺序由它决定。在判断形态或重写之前先读它。

要采用它，复制它并解决每一个 `<…>`；不允许任何 `<…>` 留进项目的文件。

- `<skill: name>` 指本技能所在技能包中的一个技能。用指向该技能在项目中安装位置的链接替换它。如果项目没有这个技能，删掉指针，保留原则。
- `<skill: the project's own …>` 代表只有本项目才有的技能。链接它，或删掉整句。
- 其余的 `<…>` 用项目 readme 的内容填写。

项目不需要的章节就删掉；只有当某个原则无处安放时才新增章节。
