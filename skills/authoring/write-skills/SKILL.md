# 编写技能

技能不是文档。它是给一个已经会编码、会推理的智能体准备的压缩操作记忆。它的职责是**可预测性**——让智能体每次运行都执行同样的*流程*，而不是产出同样的输出。只放那些会改变智能体行为的内容。

## 第一性原理

1. **触发靠 description。** frontmatter 里的 `description` 是技能加载前唯一会被读取的部分。写清这个技能做什么，以及哪些具体情境应当触发它。不要把触发规则藏进正文。

2. **把 token 当稀缺资源来花。** 假设智能体已经擅长通用推理。给出方向，让聪明的模型自行解决实现细节。一个包装型技能可以只有两句话：点名要用的能力和要遵循的技能。只有当已证实的失败需要时才添加机制。

3. **写规程，不写散文。** 优先用命令式规则、决策点和小例子。好的技能改变下一轮的行为，而不只是解释话题。并让规程匹配交付物的形态：一份"挑合适的用"的技法目录只会产出挑工具的行为，而不是一条流程——如果任务本身就是一种有形态的交互（一次访谈、一段分步推进），工作流就必须*是*那个形态，技法降级为其中的步骤。

4. **使用渐进式披露。** 让主技能文件保持简短。把冗长的 schema、示例、供应商文档或变体专属指引推进链接的 `references/` 文件，用一个只在需要时才触发的指针指过去。把可重复的脆弱操作放进 `scripts/`。把可复用的输出材料放进 `assets/`。

5. **靠使用来验证。** 当一个全新的智能体能在真实任务上正确应用它时，技能才算好——盲测运行，并在将运行它的最弱模型上测；一个只能在撰写它的前沿模型上驱动正确行为的技能，脆弱到不值得交付。编辑之后，装作自己没有任何对话历史重读一遍，删掉一切不会影响行动的内容。

6. **示例记录的是问题本身，而非解决方案。** 一个示例配得上它的 token，是因为它教智能体*识别一个反复出现的问题*——坏味道、症状、你怎么知道它不对。这才是持久的。你恰好采用的修法不是：代码会变，内置解法会过时，更糟的是规定一个下次未必适用的动作。写下失败模式及其征兆；让智能体针对当前代码现场推导修法。"每个方位上质心距离都读错导致的定向问题"能教人；"所以我们把它键在 FRONT_ARC 上"会腐烂。拿不准时，说明什么坏了、你怎么发现的，然后停在那里。

## 引导词

一个**引导词**是模型预训练中已有的一个紧凑概念，智能体在运行技能时用它来思考（如 *战争迷雾*、*曳光弹*、*red*、*tight*）。一个词就能调动模型已有的先验，用最少的 token 锚定一整片行为区域。

- 它在正文里锚定**执行**（同一个词 → 每次同样的行为），在 description 里锚定**调用**（当这个词也出现在用户的提示、文档和代码中时，技能触发得更可靠）。
- 猎取能被一个引导词取代的复述。"快、确定、低开销" → 一个 *tight* 的循环。"一个你相信的循环" → 循环变 *red*。你赢两次：token 更少，钩子更锋利。
- 弱引导词等于没说（`be thorough`——智能体本来就很 thorough）。修法是换一个更强的词（*relentless*），不是加更多句子。

## 调用

选择技能如何被触达；每种选择花费不同的成本。

- **模型调用**（默认）：保留 `description`，让智能体能自行触发它，其他技能也能到达它。代价是**上下文加载**——description 每一轮都占据上下文窗口。写丰富的触发措辞。
- **用户调用**：设置 `disable-model-invocation: true`。只有用户敲入它的名字才能调用；零上下文负担，但用户必须记得它存在。`description` 变成一行面向人类的简介。

只有当智能体或另一个技能必须无人提示地触达它时，才选模型调用。当用户调用的技能多到记不住时，加一个**路由技能**，点名其余技能以及各自何时该用。

## 描述

description 做两份工作：说明技能是什么，并列出触发它的各个不同情境（**分支**）。

- 把引导词放在最前面——调用的工作在这里完成。
- 每个分支一个触发条件。给同一分支改名的同义词就是重复；合并它们，只保留真正不同的分支。
- 删掉正文里已经写明的身份。保留触发条件，以及任何"当另一个技能需要……"式的触达从句。

## 信息层级

技能是**步骤**与**参考**的自由混合。按智能体需要每块内容的紧迫程度排序：

1. **技能内步骤** —— `SKILL.md` 里一个有序的动作。每步以一个**完成判据**收尾：让它*可检查*（智能体能分辨完成与未完成吗？），在重要的地方让它*穷尽*（"每一个被修改的模型都已被交代"，而不是"产出一份变更清单"）。模糊的判据招致过早完成。
2. **技能内参考** —— 按需查阅的定义或规则。一组扁平并列的规则没问题，不是坏味道。
3. **外部参考** —— 从 `SKILL.md` 推出到链接文件，仅当它的指针触发时才加载。

把一个概念的定义、规则和注意事项放在同一个标题下（**共置**），读其中一部分就会带出它的邻居。下推太少，顶部臃肿；下推太多，智能体需要的东西被藏住。

## 何时拆分

每次切分都花费成本，所以只在值得时才切：

- **按调用切** —— 当一个独特的引导词应当单独触发一个技能，或另一个技能必须到达它时，把一个模型调用的技能切出去。你要为新的常驻 description 支付上下文加载的成本。
- **按序列切** —— 当还没执行的步骤诱使智能体抢跑眼前这一步时，把一串步骤切出去。藏起后面的步骤，迫使当前步骤承担更多工作。征兆是**阶段压缩**：几个步骤的工作落进同一条消息，或智能体从未打开某个步骤却宣布它已完成。主技能里"进入某一步时，读它的文件"这样的指针能可靠触发，即使在较弱的模型上。

## 失败模式

用以下条目给行为失常的技能做诊断：

- **过早完成** —— 步骤还没完成就结束。先修完成判据（便宜）；只有当判据不可避免地模糊*且*你观察到抢跑时，才靠切分藏住后续步骤。当技能的职责以一份交接产物告终，把它命名为*唯一的*技能级完成条件——否则运行会终止在任何一份"感觉完成了"的中间产物上。
- **信息扣留** —— 有序工作流被过度服从：智能体为了遵守后面步骤的编排而扣留早就做出的发现，于是用户在做决定时，智能体手里却压着影响该决定的信息。任何给步骤排序的技能都必须写明逃生阀：顺序支配呈现，绝不支配披露。
- **侥幸通过** —— 一次验证运行之所以成功，只因为用户或外部世界主动送来一个关键输入。结果是对的，但流程并没有产出它；把那个引出信息的探查编码成显式步骤，而不是指望好运重演。
- **重复** —— 同一含义出现在两处。保持**单一事实来源**。
- **沉积** —— 因为"加东西感觉安全"而堆积起来的过时层。有意识地修剪。
- **战例** —— 把一条教训写成那次教会它的变更的全程记录：函数名、调过的值、一个 bug 的轨迹。这些细节过时得很快，还把可迁移的规则埋掉。写出原则和要警惕的征兆；把机制留给代码库。一个具体的试金石能为它定基；成段的试金石会把它淹死。
- **实现索引** —— 技能去指认今天的源文件、行号、当前字面量或确切的内部函数，而它真正的职责是教判断。这些定位符会腐烂，让智能体追着旧机制跑。把持久的原则、症状、验收标准和参考资产留在技能里；把任务特定的实现笔记放进当前的规格说明。如果代码位置重要，让智能体去代码库里找当前的属主。
- **蔓延** —— 就算每一行都是活的也还是太长。用阶梯来治：把参考藏到指针后面，按分支或序列切分。
- **无效句** —— 模型默认就会服从的一行。逐句单独测试；测试不通过时，删掉整句，而不是修剪措辞。

## 形态

除非有足够强的理由，否则使用这个结构：

```markdown
---
name: short-verb-phrase
description: What this does. Use when ...
---

# Skill Title

One short paragraph defining the job.

## Workflow

1. Do the first load-bearing thing.
2. Make the key decision.
3. Produce or verify the artifact.

## Rules

- Keep the constraints that prevent common mistakes.
- Link only the references that should be loaded conditionally.
```

## 编辑要点

创建或修订技能时：

- 命名优先用小写连字符式的**动作 + 复数名词**：`audit-tests`、`write-skills`、`compare-screenshots`。保持文件夹与 frontmatter 的 name 完全一致。当复数化会扭曲含义时允许自然的例外；这是新名字的默认做法，不是强制重命名现有技能的要求。
- 把 description 写得足够具体，不靠正文也能触发。
- 从正文删除任何"何时使用"章节。
- 删除过时的历史、署名、占位符和安装说明。
- 删除文件路径、行号、当前常量和实现旋钮，除非这个技能明确就是一份代码导航手册。优先持久的原则加一条"查看当前代码"的指令。
- 一条强规则胜过几条互相重叠的要点。
- 有合适之处就把复述重构成引导词。
- 让示例小而真实。
- 不添加 README、changelog 或辅助文档，除非它们是技能会告诉智能体何时去读的真正参考。
- 有校验器时就运行技能校验器。

## 完成

当它的元数据能正确触发、正文短到一遍就能读完、并且一个全新的智能体能照着走而不问"这个技能为什么存在"时，这个技能就完成了。
