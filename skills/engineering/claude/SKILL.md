# Claude

Claude Code 是 PATH 上的一个独立智能体（`claude`），共享当前工作树且已完成认证。把它用作第二意见或受托工作者，而不是事实标准：验证它的主张，对任何改动负责，并保持其任务契约窄而有界。

## 默认值

使用 `claude -p --model opus --effort high`，除非用户或任务要求不同的模型或思考级别。

- **模型：** 接受 `opus`、`sonnet`、`fable` 等别名或完整模型名。默认 `opus`。
- **思考级别：** 传递 Claude Code 的 `--effort` 标志。有效级别为 `low`、`medium`、`high`、`xhigh` 和 `max`。默认 `high`。
- **成本护栏：** 对于探索性请求，当用户给出预算或任务可能铺开时，加上 `--max-budget-usd <amount>`。

示例：

```sh
claude -p --model opus --effort high "<prompt>"
```

## 给 Claude 下提示

像操作员一样给 Claude 下提示：紧凑、分块结构化，并明确说出你需要的产物。更锐利的契约胜过更高的努力程度。

- **一次运行一个任务。** 把评审、实现和文档拆进不同的提示。
- **相关时点名仓库里的技能。** Claude 能读取仓库文件；说"文档遵循 write-docs"或"遵守 refactor-clean：不要兼容性包装器"，而不是把那些技能粘贴进提示。
- **分块，只在有用处添加：**
  - `<task>`——具体任务、上下文和预期终态。
  - `<output_contract>`——精确的响应形状，价值最高的放前面。
  - `<default_follow_through>`——采取低风险的解读并继续推进；只有当缺失的细节影响正确性、安全性或不可逆操作时才停下。
  - `<verification_loop>`——对照要求检查结果，定稿前先行修订。
  - `<grounding>`——每条主张都以代码或工具输出为据；推断要标注为推断。
  - `<action_safety>`——把 diff 的范围收紧；不夹带顺手的重构。
- **反模式：** 模糊的提示、混杂的任务、没有输出契约、要求它"再想想"而不是收紧任务，以及不加核验证据就接受它的回答。

## 咨询

当用户征求 Claude 的看法，或第二智能体的解读能实质降低风险时，用 Claude 做咨询。保持只读取向，除非用户明确要求它编辑。

1. 要证据，不要感觉：要求给出文件路径、观察到的行为、命令输出，或标注过的推断。
2. 评审时优先使用只读工具面：
   `--tools "Read,Grep,Glob,Bash" --permission-mode dontAsk`。
3. 采取行动前先对照代码甄别每一条发现。报告 Claude 标记了什么、你接受了什么、你驳回了什么。

## 实现——仅在明确要求时

只有当用户指名让 Claude 做该任务时才把实现委托给它。绝不主动把工作交给它，也绝不未经新的要求就转委托后续工作。

1. 把任务切得锋利：目标、约束、允许的范围和验证方式。规定不足的任务留在你手里，直到一个全新的智能体也不可能误读它。
2. 从干净的工作树开始，或记录基线提交，使 Claude 的 diff 与你的可分离。告诉 Claude 不要把临时文件（探针、转储、笔记）留在树里——它的 diff 必须只包含交付物。
3. 按任务需要做什么来选择权限：
   - 读取/评审：`--tools "Read,Grep,Glob,Bash" --permission-mode dontAsk`。
   - 小范围编辑：加入编辑工具，并在提示中明确允许的路径。
   - 大范围自主工作：仅在专用 worktree 中使用 `--dangerously-skip-permissions`，提示必须由你亲自撰写，事后必须做 diff 评审。
4. 默认用 `--output-format text` 捕获响应。仅当调用方需要结构化元数据时才用 `--output-format json`。
5. 结果由你负责：检查 diff、运行相关测试，然后才汇报。"Claude 说做完了"不等于做完了。

## 存活问题

`claude -p` 是一次联网、已认证的非交互运行。如果失败，先对失败分类再重试。

- 认证失败：除非用户要求，不要修复凭据；上报阻塞点。如果沙箱中的 `claude -p` 报 `Not logged in`，则在获得所需批准后重试一次，因为本地认证可能依赖钥匙串/会话访问。
- 沙箱/网络失败：若该命令对任务重要，则在获得所需批准后重跑。
- 长时间运行：在提高努力程度之前，优先考虑 `--max-budget-usd` 或更窄的提示。
- 工作区信任：`-p` 会跳过交互式信任对话框，因此只在你有意信任的仓库或 worktree 中运行它。

## 规则

- 以 `claude -p --model opus --effort high` 作为默认调用。
- 允许用户用自然语言改写模型和努力程度；把它转译成 `--model` 和 `--effort`。
- 除非委托是明确发出的，否则不让 Claude 的写入进入工作树。
- Claude 编辑期间不要触碰同一个工作树。
- 把 Claude 的输出当作待验证的证据，而不是可转述的权威。
