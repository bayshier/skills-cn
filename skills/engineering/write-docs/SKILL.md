# 撰写文档

文档是一部**术语表**：它点名活动的部件，说明每个部件为何存在，并承载读者无法通过 grep 推导出的原则。代码是"现在存在什么"的事实来源——文档绝不能与它赛跑。落笔之前，先问这个统领本技能的问题：**读者直接读代码，能否更快、更可靠地得到这个信息？**如果能，就把他们指向代码，而不是把代码抄进来。

## 保留与舍弃

保留——读者无法靠 grep 得到这些：

- 为什么（WHY）：一个东西为何存在、某次拆分背后的原则、文件名透露不出来的分类体系。
- 非显而易见的发现：平台怪癖、"删掉这个，X 会因为 Y 而坏"、两个文件间默默共享的契约。
- 指向事物所在位置的指针，以及那里住着哪一类东西、纳入的规则是什么。

舍弃——代码或其 git 历史已持有这些，副本只会腐烂：

- 精确名册：场景名、用例表、辅助函数清单、类 id、文件清单、命令/标志矩阵。
- 叙事与变更日志："我们把 X 改名了"、"旧的 Y 作为重复项被移除"、试过又放弃的东西。
- 精确计数、tick 值、当前常量、行号——任何只是复述代码的东西。

## 指路，不要抄录

当你想罗列具体条目时，点名拥有它们的目录或那个单一文件，把读者送去那里——**宁选目录不选文件，宁选事实源注册表不选转抄副本。**描述一个辅助模块时，说它装载哪一*类*辅助器、纳入其中的规则是什么，而不是它当前的名册。为锚定一条原则，给一个具体示例无妨；完整清单就是坏味道。"对战数据住在定义它们的表里；id 以类注册表为键"在下一次编辑之后仍然为真——把两者转抄出来则不然。

## 每个事实只有一个家

每个事实恰好有一个规范的家；其他所有文档都链接到它。跨文档的重复是维护缺陷——副本会漂移，读者分不清哪个是当前版本。根/全局文档保留一小节加指向子文档的指针。当两份文档解释同一件事时，选定中心，把另一份削减成一个指针。

## 链接成树，向下流动

文档构成一棵可从单一根/中心文档到达的树：中心链接到每个子文档，子文档再链接到它之下任何模块级文档。导航**向下**流动——读者从根出发沿链接深入，整棵树都可从根到达。文档向上链接父级、或横向链接兄弟，**只为了复用已经住在那里的事实**——应用文档指向中心的部署小节而不是重述它，边界文档点名它让位给的兄弟文档。这正是"一个家"规则在起作用。你*不*要加的是那种机械的"属于 X"回链：它不携带信息，是噪音，而且树本来就能从根导航，不需要它。

## 编辑遍次

修剪既有文档时，见即删：代码可发现的条目枚举、变更日志与叙事，以及任何复述代码的句子。然后以一个没有对话历史的陌生人的身份重读幸存内容——留下的每一行都应是一条原则、一个"为什么"，或一个指针。如果一句话变成链接后同样为真、同样有用，就让它成为那个链接。
