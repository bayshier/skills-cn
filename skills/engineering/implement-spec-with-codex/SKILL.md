# 用 Codex 实现规格说明

严格按 [implement-spec](../implement-spec/SKILL.md) 运行——同样的循环、同样的门禁、同样的维护检查点——只是代码由 Codex 编写。调用本技能即是显式请求，授权在 [codex](../codex/SKILL.md) 技能之下进行 `codex exec` 委派。

## 角色分工

- **Codex 负责实现——只要可能。**把每个实现遍次默认交给一次 `codex exec`，切片切得锋利，并按 codex 技能的方式撰写提示词（提示词分块、沙箱选择、exec 存活检测）。在 implement-spec 会扇出子智能体的地方，同样把独立切片作为并发的 exec 在各自 worktree 中运行。
- **你负责编排与评审。**规格说明循环仍归你：挑选下一个切片、让计划与代码对齐、端到端撰写每条提示词、整合 diff、运行门禁、评审合并后的代码树、提交、更新交接内容、运行维护检查点。这些一律不委派。

只有当把一个遍次切成锋利的切片反而比亲自完成代价更高时才自己做——微小修补、计划对齐、整合冲突。

## 规则

- 每个结果都由你负责：亲自读完整 diff、亲自运行验证。"Codex 说完成了"永远不等于完成。
- 视觉结果在这里要加倍严格执行 implement-spec 的两项额外证明（生产路由像素 diff + 未受暗示的评审）：沙箱中的 Codex 从未见过自己的变更渲染出来，所以一个完全错过生产渲染路径的遍次会带着"完全已验证"的样子到达。
- 沙箱中的 Codex 交付的是它从未见过运行的代码——亲自用浏览器验证每个视觉切片，并为修复轮次预留预算。把红色门禁作为恢复执行的后续任务连同失败证据发回；只有当自己修比重新提示更省时才自己修。
- 提交卫生仍归你：每次提交前评审合并后代码树的变更清单，与 implement-spec 对整合评审者的要求完全一致。
